# Playground 玩点

一个可自行部署的 H5 小游戏网站。访客无需登录即可游玩；创作者注册后可以在浏览器中编写 HTML、CSS、JavaScript，保存草稿并发布游戏。

## 启动

需要 **Node.js 24 或以上版本**（使用内置 `node:sqlite`）。没有第三方运行时依赖，也没有额外构建步骤。

```bash
cd /workspace/games
npm start
```

默认监听端口 `3000`。开发时使用 `npm run dev` 自动重启服务。数据库默认保存在 `.data/games.sqlite`，首次启动自动创建表并加入三款示例游戏。

## 使用 Docker 运行

需要 Docker Engine / Docker Desktop 和 Docker Compose v2，无需在宿主机安装 Node.js。

在项目根目录执行：

```bash
docker compose up -d --build --wait
```

启动后，通过运行 Docker 的主机 IP 和 `3000` 端口访问网站。Compose 会等待健康检查通过后返回。容器使用 Node.js 24 官方镜像，以非 root 用户运行。

可选：复制 `.env.example` 为 `.env` 后修改配置。`APP_PORT` 控制宿主机端口，例如改为 `8080` 后通过主机的 `8080` 端口访问；容器内部仍使用 `3000`。如果部署 HTTPS 站点，将 `PUBLIC_ORIGIN` 设置为真实站点来源，并设置 `COOKIE_SECURE=1`。本地 HTTP 开发保持 `COOKIE_SECURE=0`。修改配置后重新运行启动命令。

```bash
# 查看状态和日志
docker compose ps
docker compose logs -f games

# 拉取代码更新后，重新构建并启动
git pull
docker compose up -d --build --wait

# 停止并移除容器，保留账号和游戏数据
docker compose down

# 在独立镜像构建阶段运行检查和集成测试
docker build --target test -t playground-h5:test .
```

数据库保存在名为 `<Compose项目名>_playground_data` 的 Docker 数据卷中，挂载到容器 `/data`。重启、重建和普通 `docker compose down` 均会保留数据。**`docker compose down -v` 会删除数据卷及全部账号和作品。** 使用相同的项目目录 / Compose 项目名重启，才能复用原数据卷。

Docker 初次运行使用独立的新数据库，不会自动导入本机 `.data` 中的已有数据。镜像构建不会包含 `.data`、`.env` 或 Git 历史。需要迁移已有数据时，先停止写入，再将完整数据库目录复制到数据卷，并确保容器用户 UID/GID `1000:1000` 可写。

不使用 Compose 时，也可以：

```bash
docker build -t playground-h5:local .
docker volume create playground_data
docker run -d --name playground --restart unless-stopped --init \
  -p 3000:3000 \
  --mount type=volume,src=playground_data,dst=/data \
  playground-h5:local
```

公网部署仍需配置 HTTPS 反向代理和域名；Docker 启动本身不会提供公网域名。

## 已实现

- **星野纪元**：内置 H5 多人 RPG，入口为 `/#world`，支持三种职业、共享地图、实时位置同步、协作打怪、范围技能、结晶采集、三阶段主线任务、升级、武器强化、药水、营地恢复、死亡复苏、世界聊天与账号存档。
- 响应式中文游戏大厅，支持关键词搜索、分类和热门 / 最新排序。
- 贪吃蛇、记忆翻牌、接星星三款完整游戏及可修改的模板。
- 注册、登录、退出；密码使用随机盐和 scrypt 派生，会话保存在数据库中。
- HTML / CSS / JavaScript 编辑器，800 毫秒防抖预览，支持 Ctrl / ⌘ + Enter 手动刷新。
- 保存私有草稿、发布、编辑、取消发布、删除自己的游戏。
- 每款作品有 `/#play/<游戏ID>` 分享地址，可由其他访客游玩；记录启动次数。
- 玩家全屏、重新开始和复制分享链接。
- 游戏内容通过沙盒 iframe 和独立 CSP 响应运行，无法读取主站会话或请求网络。

## 使用流程

1. 点击「创建游戏」，选择一个模板并修改代码。
2. 在下方填写名称、简介、分类和封面主题。
3. 点击「保存草稿」或「发布游戏」，按提示注册或登录。
4. 发布后，游戏会出现在大厅。打开游戏页，点击「分享」复制地址。
5. 在「我的作品」中继续编辑、取消发布或删除作品。

HTML 编辑栏用于游戏页面内容；CSS 和 JavaScript 分别填入对应栏。资源可使用 data URL 内嵌。创作台内的用户游戏不支持外部脚本、远程资源和网络 API。预览保留约 10 分钟，过期后点击「运行预览」重新生成。未保存的代码仅保留在当前页面，离开前请保存。

## 配置与部署

### 星野纪元：游玩与存档

1. 启动服务后，点击导航中的「星野纪元」，或访问 `http://localhost:3000/#world`。
2. 选择游侠、骑士或法师，点击「游客试玩，立即进入」即可开始，无需注册；也可登录账号创建角色。每个账号一个角色，之后进入会自动读取已有职业与进度。
3. WASD / 方向键移动，点击地面前往，点击怪物锁定；空格攻击、Q 范围技能、E 采集、R 喝药、C 走回营地。手机可长按方向按钮并点击技能按钮。返回营地不会自动寻路，遇到水域需要绕行。
4. 击败怪物、收集结晶，回营地靠近守林人艾拉交任务。在「背包」购买药水或强化武器，达到 3 级后可挑战东侧古树守卫。
5. 使用不同账号、浏览器配置或设备连接**同一个服务器地址**，即可看到彼此并协作战斗。聊天位于「世界」页签。同一账号在新窗口进入后，旧窗口失去角色控制权。

账号角色保存在 SQLite 的 `world_characters` 表中，与账号绑定，包含位置、职业、生命、等级、经验、金币、背包、武器强化和任务进度。每 5 秒自动存档，奖励、采集、购物、交任务、复苏和手动存档即时写入。正常离场也会保存；浏览器突然关闭或进程被强制结束时，最近不超过约 5 秒的位置 / 受伤变化可能尚未保存。网络中断时界面会标明未确认新存档，超过 15 秒会离线，重新进入即可读档。

游客使用独立的 `HttpOnly` Cookie 身份，进度由服务器保存在 `world_guests` 表中，不会创建注册账号。游客可体验同一世界的战斗、任务、背包、升级和聊天，自动 / 手动保存规则与账号角色相同。每次点击进入游客试玩会续期 7 天；有效期内刷新页面或重启服务后，可用同一浏览器继续。清除 Cookie、到期、换浏览器或无痕窗口关闭后，无法找回原游客身份；过期记录会被自动清理。游客身份不能访问创作台的私有作品或发布接口。

**注册后接续游客进度：**在原浏览器、原站点地址进入游客角色后，点击「注册账号，永久保留进度」，或使用页面的注册入口。注册成功会自动将当前游客的职业、等级、经验、位置、生命、金币、背包、强化、任务与复苏记录转入新账号，角色名改为注册用户名；不会重新创建初始角色。此后存档不受游客 7 天有效期限制，并可在其他设备登录该账号继续。

注册、账号会话和进度转存使用同一个数据库事务；注册失败会保留游客存档。迁移使用最新的服务端内存状态，成功后旧游客身份失效，不能重复领取。登录已有账号不会迁移或覆盖其角色。前端通过 `/api/world/register` 提交注册，以携带限定在 `/api/world` 路径下的游客 Cookie；普通 `/api/register` 仍保留用于兼容没有游客身份的客户端。请不要在试玩和注册之间切换 `localhost` / `127.0.0.1` 等不同站点地址，它们有不同的 Cookie 身份。

保存进度来自服务器计算；客户端不能上传金币、等级等字段覆盖存档。服务重启保留账号和角色，怪物、采集点及短期聊天记录会重置。复苏保留任务和物品。备份与迁移请保留完整的 `DATA_DIR`，账号数据库和角色存档一起迁移。

这是一版**单进程、小规模多人 RPG 原型**，采用约 160 毫秒一次的 HTTP 状态交换、20 Hz 服务端模拟，设有 64 个在线角色的入场上限。该数字是配置上限，未经 64 人并发压测，不代表已验证容量；尚不具备商业 MMO 的分区、跨服、公会、交易、匹配和大规模运维能力。勿将多个独立进程指向同一个数据库运行世界；它们不会共享实时怪物和玩家状态。

内置 RPG 使用受信任的专用客户端与后端 API。创作台发布的用户游戏仍在禁用网络的沙盒内运行，不能直接使用 MMO API；它不是可直接粘贴到创作台中的单文件模板。修改世界规则请编辑 `public/world-rules.js` 与 `world.js`。

### 服务配置

| 变量            | 默认值           | 用途                                                           |
| --------------- | ---------------- | -------------------------------------------------------------- |
| `PORT`          | `3000`           | HTTP 监听端口                                                  |
| `HOST`          | `0.0.0.0`        | 监听地址                                                       |
| `DATA_DIR`      | 仓库下 `.data`   | SQLite 数据目录，应挂载持久化磁盘                              |
| `PUBLIC_ORIGIN` | 按请求 Host 校验 | 公网部署时设置为完整站点来源，例如 `https://games.example.com` |
| `COOKIE_SECURE` | 未设置           | HTTPS 部署时设置为 `1`，使会话 Cookie 仅通过 HTTPS 发送        |

生产环境应以常驻 Node 进程运行，在前面配置 HTTPS 反向代理。设置真实 `PUBLIC_ORIGIN`、`COOKIE_SECURE=1`，并保留原始 Host 请求头。注册限流依据直连来源 IP；共用反向代理时，建议由入口代理按真实来源设置限流。应用不会信任任意转发 IP 请求头。

这是带持久化数据库的单机 MVP，不适用于只有静态托管或文件系统临时性的部署平台。备份时使用 SQLite 在线备份，或先停止服务再复制整个数据目录（包含 WAL 文件）。不要提交数据库到 Git。发布云开发环境快照与将网站部署到公网是两件事；当前仓库不包含公网域名或托管服务配置。

当前注册对所有访问者开放，尚未包含作品审核、管理员后台、账号找回和文件上传。游玩计数为启动次数，不去重。

## 项目结构

- `server.js`：HTTP API、会话认证、SQLite 存储与沙盒游戏页面。
- `world.js`：多人世界模拟、服务端动作校验、共享怪物和角色持久化。
- `public/world-rules.js`：职业、地图、任务与成长规则。
- `public/world-client.js` / `public/world.css`：Canvas 游戏客户端、手册、背包、聊天和触控布局。
- `public/app.js`：页面路由、游戏大厅、创作台和播放器。
- `public/templates.js`：内置游戏源码及沙盒页面构建。
- `public/styles.css`：桌面和移动端样式。
- `test/server.test.js`：独立的 API 集成测试。
- `test/world.test.js` / `test/world-api.test.js`：战斗与采集规则、角色隔离、双账号同步、断线、自动保存及实际服务重启后的读档测试。
